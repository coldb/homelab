# Phase 1 secrets

These seven examples contain no credentials and are excluded from Flux. Fill
copies outside this repository, encrypt them with the production SOPS recipient,
then add only the encrypted outputs to this directory's `kustomization.yaml`.
`planner-db-ca` is generated by CNPG; do not create a replacement CA secret here.

| Template | Value to supply |
| --- | --- |
| `planner-db-owner.secret.example.yaml` | Independent random bootstrap-owner password |
| `planner-migrations-db.secret.example.yaml` | Independent random migration password |
| `planner-api-db.secret.example.yaml` | Independent random runtime/operator password |
| `planner-clerk.secret.example.yaml` | Backend secret from the dedicated Clerk production instance |
| `planner-registry.secret.example.yaml` | Forgejo username and package-read token |
| `planner-backup.secret.example.yaml` | AWS credential scoped to the Planner backup bucket/prefix |
| `planner-cloudflare.secret.example.yaml` | JSON credential file for a locally managed Cloudflare tunnel |

Generate a **different** database password for each of the first three files:

```sh
openssl rand -hex 32
```

Each invocation produces 32 random bytes encoded as 64 hex characters (256 bits).
Paste one result into one password field, then run it again for the next field.
Hex avoids YAML quoting and connection-URL escaping problems. The launcher also
percent-encodes credentials when constructing the verified-TLS connection URL.
Keep the fixed `username` values unchanged. Never reuse these passwords for other
services. Provider keys, registry/AWS credentials and tunnel credentials must come
from their providers; random strings cannot replace them.

Use `stringData` as shown: **no manual base64 encoding is needed**. Base64 is only
an encoding; SOPS/age provides the encryption needed for Git. For the registry
template fill valid JSON with the real username/token. For the tunnel, use
`cloudflared tunnel login` followed by `cloudflared tunnel create planner`, then
copy the entire resulting `<UUID>.json` content into the `credentials.json`
string. Keep the account-wide `cert.pem` off the cluster. Put the same UUID in
`apps/production/planner/cloudflared-config.yaml`. This deployment intentionally
uses local ingress configuration and JSON credentials instead of a remotely
managed tunnel token, so its private-path rules are versioned in Git.

From the homelab root, prepare local copies with restricted permissions:

```sh
umask 077
planner_secret_dir=$(mktemp -d "${XDG_RUNTIME_DIR:-/tmp}/planner-secrets.XXXXXX")
cp config/production/planner/secrets/*.secret.example.yaml "$planner_secret_dir/"
```

Edit those copies. After filling **all** values, encrypt them using the repository's
existing production rule (no private age key is needed to encrypt):

```sh
(
  set -eu
  planner_secret_path=config/production/planner/secrets
  planner_encrypted_dir=$(mktemp -d "$planner_secret_dir/encrypted.XXXXXX")
  trap 'rm -r -- "$planner_encrypted_dir"' EXIT

  for template in "$planner_secret_path"/*.secret.example.yaml; do
    name=$(basename "$template" .secret.example.yaml)
    input="$planner_secret_dir/$name.secret.example.yaml"
    output="$planner_secret_path/$name.enc.yaml"
    if rg -q 'REPLACE_ME' "$input"; then
      printf 'Fill the values in %s first\n' "$input" >&2
      exit 1
    else
      planner_scan_status=$?
      if [ "$planner_scan_status" -ne 1 ]; then
        printf 'Could not scan %s for placeholders\n' "$input" >&2
        exit "$planner_scan_status"
      fi
    fi
    sops --encrypt --encrypted-regex '^(data|stringData)$' \
      --filename-override "$output" "$input" > "$planner_encrypted_dir/$name.enc.yaml"
  done

  mv -- "$planner_encrypted_dir"/*.enc.yaml "$planner_secret_path/"
)
```

The command installs the encrypted files only after every input has encrypted
successfully. An unfilled placeholder or encryption failure preserves existing files. Run
`sops filestatus <file.enc.yaml>` to inspect encryption status and
`sops <file.enc.yaml>` to inspect/edit with the production private key configured.
Never commit a file containing populated plaintext values. Remove the temporary
copies when finished:

```sh
rm -r -- "$planner_secret_dir"
```

Replace `resources: []` in this directory's `kustomization.yaml` with:

```yaml
resources:
  - planner-api-db.enc.yaml
  - planner-backup.enc.yaml
  - planner-clerk.enc.yaml
  - planner-cloudflare.enc.yaml
  - planner-db-owner.enc.yaml
  - planner-migrations-db.enc.yaml
  - planner-registry.enc.yaml
```

The production age recipient is selected from the root `.sops.yaml`. Flux uses
`flux-system/sops-age` for decryption, as elsewhere in this repository. Validate
the completed release with `python3 scripts/planner/check.py --ready` before
activation. It checks encryption structure, image digests and matching release
inputs, but cannot establish credential validity without a rollout.

After password/key rotation, let CNPG reconcile DB role passwords and explicitly
roll the affected web/tunnel pods. Environment variables are read at process
start. Apply the secret changes before rolling consumers; retain a usable operator
connection and inspect CNPG managed-role status. A secret update alone does not
restart a completed migration Job.
